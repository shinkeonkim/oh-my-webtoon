# 4. 배포 (oh-my-homelab)

oh-my-homelab 의 "서비스 레포가 deploy/ 를 소유하고, 홈랩 레포는 Application + 시크릿 + NetworkPolicy 만" 패턴
(url-shortener, maeil-mail 과 같음).

```
my-webtoon (이 레포)
  push main ─▶ release.yml: 테스트 → ghcr.io/shinkeonkim/oh-my-webtoon:sha-xxxxxxx push
                             → deploy/kustomization.yaml 의 newTag 를 그 sha 로 커밋
oh-my-homelab
  helm-charts/apps/my-webtoon.yaml          ArgoCD Application (sources: 이 레포 deploy/ + 아래 둘)
  helm-charts/secrets/my-webtoon/           my-webtoon-secrets (APP_PASSWORD, SESSION_SECRET) — SOPS
  helm-charts/network-policies/my-webtoon/  ingress: cloudflare-tunnel·traefik / egress: DNS·인터넷
ArgoCD ─▶ my-webtoon 네임스페이스: Deployment(1) + PVC(longhorn-r1, 2Gi) + Service + Ingress
Cloudflare Tunnel Public Hostname: my-webtoon.shinkeonkim.com → http://my-webtoon.my-webtoon.svc.cluster.local:80
```

## 사람이 직접 해야 하는 것

oh-my-homelab 의 `docs/setup/my-webtoon_배포_요청사항.md` 에 순서대로 있다. 요약:

1. GitHub 에 `shinkeonkim/oh-my-webtoon` 레포를 만들고 push → Actions 가 첫 이미지를 올린다
   (레포가 private 이면 ghcr 패키지도 private → imagePullSecret 필요)
2. oh-my-homelab PR merge
3. Cloudflare Zero Trust → Tunnels → Public Hostname 추가
4. 확인: `curl -I https://my-webtoon.shinkeonkim.com/healthz`

## 데이터 영속성

| 상황 | 데이터 |
|---|---|
| 파드 재시작 / 새 이미지 배포 / 노드 재부팅 | 남는다 — PVC(`my-webtoon-data`, Longhorn) |
| `deploy/` 에서 PVC 를 빼거나 Application 삭제 | 남는다 — PVC 에 `Prune=false,Delete=false` |
| 볼륨이 있던 노드 디스크 고장 (`longhorn-r1` = 복제본 1개) | 볼륨은 잃지만 **하루 한 번 백업**이 Mac NFS(`my-webtoon-backup`, `nfs-mac`, Retain)에 있다 |
| 직접 보관 | `/settings` → 평가 JSON 내려받기 / 가져오기 |

백업은 `BACKUP_DIR=/backup` 에 `my-webtoon-<시각>.db`(전체) + `reviews-<시각>.json`(평가만), 최근 14개.

복구:
```bash
POD=$(kubectl -n my-webtoon get pod -o name | head -1)
kubectl -n my-webtoon exec $POD -- ls /backup
kubectl -n my-webtoon exec $POD -- cp /backup/my-webtoon-<시각>.db /data/my-webtoon.db
kubectl -n my-webtoon delete $POD   # 재시작 (Deployment 가 다시 띄운다)
```
평가만 되돌리려면 `reviews-<시각>.json` 을 `/settings` 에서 가져오면 된다.

## 비밀번호

- 처음엔 시크릿 `APP_PASSWORD`. `/settings` 에서 바꾸면 PBKDF2 해시가 DB(`meta.password_hash`)에 저장되고 그게 우선한다.
  바꾸면 다른 기기 로그인은 모두 풀린다.
- 잊었을 때 — DB 해시를 지우면 다시 `APP_PASSWORD` 로 로그인된다:
  ```bash
  kubectl -n my-webtoon exec deploy/my-webtoon -- python -c \
    "import sqlite3; c=sqlite3.connect('/data/my-webtoon.db'); c.execute(\"DELETE FROM meta WHERE key='password_hash'\"); c.commit()"
  ```

## 공개 범위

로그인 없이: 작품 목록(`/comics`), 작품 상세, 평가 기록(`/me`, 메모 제외) — 읽기만.
로그인 필요: 추천, 평가 남기기, 수집, 설정.

## 운영 메모

- 첫 배포 직후엔 데이터가 0개 → 크롤러가 바로 한 번 돈다(시드 2~3분 + 300개 8분). 6시간마다 300개씩 늘어난다.
  급하면 `/crawl` 화면의 "지금 한 번 수집하기".
- 로그: Grafana Loki `{namespace="my-webtoon"}`
- 로컬에서 미리 수집한 DB 를 올리고 싶으면 위와 반대로 `kubectl cp` 후 파드 재시작
