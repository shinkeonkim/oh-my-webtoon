# 2. 크롤링

## 네이버 시리즈 페이지 구조 (2026-10 확인)

| 페이지 | 경로 | robots.txt | 쓰임 |
|---|---|---|---|
| 장르/전체 목록 | `/comic/categoryProductList.series` | **Disallow** | 쓰지 않는다 |
| 코믹스 홈 | `/comic/home.series` | 허용 | 시드 |
| TOP100 | `/comic/top100List.series?rankingTypeCode=DAILY&categoryCode=88&page=2` | 허용 | 시드 (3 랭킹 × 6 분류 × 5페이지) |
| 매일 10시 무료 | `/comic/specialFreeList.series?page=N` | 허용 | 시드 + 기간 한정 무료 정보 |
| 작품 상세 | `/comic/detail.series?productNo=N` | 허용 | 작품 데이터 + 연관 작품 링크 |

목록이 막혀 있어서 **시드 → 상세 → 상세 안의 링크(작가의 다른 작품, 이 장르 인기작, TOP10)** 순서로 넓혀 가는
BFS 를 쓴다. 시드만으로도 약 1,200개 작품 번호가 모이고, 상세 페이지마다 20개 남짓 링크가 더 나온다.

## 상세 페이지에서 뽑는 것

`crawler/parser.py` 맨 위 docstring 에 HTML 조각과 함께 정리돼 있다. 핵심만:

- 무료 정보: `<div class="area_text_information"><strong>3화</strong> 무료</div>`
  - `N화 무료` / `N권 무료`(단행본) / `전화 무료` / `전권 무료` / 표시 없음(=0)
- 총 회차: `<h5 class="end_total_episode">총 <strong>349</strong>화</h5>`
- 해시태그: `<meta name="description" content="349 화 연재중, #COMIC, #무협, #먼치킨, ... 줄거리: ...">`
- 19금 작품은 로그인 페이지(`nid.naver.com`)로 리다이렉트 → `skipped` 로 표시하고 건너뜀
- 기간 한정 무료("33화 무료 50일 남음")는 상세 페이지엔 기간이 안 나와서 무료관 목록에서 따로 모은다(`free_promos`)

## 주간 갱신

총 화수·연재중/완결·무료 화수는 계속 바뀐다. 수집한 지 7일(`RECRAWL_AFTER_DAYS`)이 지난 작품을 오래된 것부터 다시 가져온다.
한 번 실행(300개)에서 **갱신에 최대 절반**, 나머지는 새 작품 발견에 쓰고, 한쪽이 모자라면 남는 몫을 다른 쪽이 쓴다
(`runner.plan_batch`). 3시간마다 400개면 하루 최대 1,600개 갱신 → 약 11,000개까지는 매주 한 바퀴. 그보다 많아지면
`/crawl` 의 "갱신 밀림" 숫자가 쌓이니 `CRAWL_BATCH_SIZE` 나 `CRAWL_INTERVAL_HOURS` 를 조정한다.

갱신할 때 총 화수·무료 화수·연재 상태·전부 무료 여부를 이전 값과 비교해 달라진 것을 `comic_changes` 에 남긴다
(`db.upsert_comic`). 무료관에 새로 걸린 기간 한정 무료도 'promo' 로 남긴다. 이게 `/news`(소식)와 카드의 '무료 +N' 배지가 된다.
처음 수집한 작품은 기록하지 않는다 — 소식이 아니니까.

## 어떤 작품부터 모으나

큐에 쌓인 작품이 많으면 순서가 중요하다. 시드(TOP100·무료관)에서 온 것을 먼저, 그다음은 **여러 상세 페이지에서 링크된 횟수(`refs`)
가 많은 순**으로 가져온다. 여러 작품의 '연관 작품'·'이 장르 인기작'에 자주 뜨는 작품일수록 인기작일 가능성이 높아서,
같은 시간에 쓸모 있는 데이터가 더 빨리 쌓인다. (2026-10-25 기준 대기 1,695개)

## 제외 장르 (`EXCLUDED_GENRES`, 기본 `BL`)

지금은 개인용이라 BL 은 모으지 않는다. 나중에 서비스로 열 때 값만 바꾸면 된다(쉼표로 여러 개, 비우면 전 장르).

- 시드: 그 장르의 장르별 TOP100 은 열지 않는다. 전체 TOP100·연관작 링크로 섞여 들어온 건 상세 페이지에서 장르를 보고 거른다.
- 거른 작품은 저장하지 않고, 그 페이지의 링크도 따라가지 않는다. 큐에는 `skipped / 제외 장르:BL` 로 남아 다시 요청하지 않는다.
- 앱이 시작할 때 `db.apply_genre_exclusion()` 이 설정과 DB 를 맞춘다: 제외 장르 작품(과 그 평가)을 지우고,
  플래그에서 빠진 장르의 `skipped` 항목은 `pending` 으로 되돌려 다음 수집에서 다시 가져온다.

## 텍스트로 검색해서 가져오기는?

네이버 시리즈 검색(`/search`)은 robots.txt 가 막고 있어서 서버가 대신 검색하지 않는다. 대신 평가하기 화면에서
내 브라우저로 네이버 검색 결과를 여는 버튼을 주고, 찾은 작품 주소를 붙여 넣어 가져오게 했다.

## 내가 시리즈에서 본 작품 가져오기 (`/import/series`)

네이버 아이디로 로그인(OAuth)은 이름·이메일 같은 프로필만 주고 시리즈 시청·구매 기록은 주지 않는다. '내 서재'(`/my/library`,
`/my/purchase`)는 로그인이 필요하고 robots.txt 도 막는다. 서버가 내 네이버 비밀번호나 쿠키를 받아 대신 들어가는 건
보안상 안 되는 일이라, **북마클릿**으로 푼다:

1. `/import/series` 의 버튼을 북마크바로 끌어 둔다.
2. 내 브라우저로 시리즈 '내 서재'를 열고(끝까지 스크롤) 북마크를 누르면, 그 페이지 HTML 안의 `productNo=` 를 모아
   `/import/series?nos=…` 를 새 탭으로 연다. 서버는 네이버에 아무 요청도 하지 않는다.
3. 미리보기에서 수집된 만화만 보여 주고(소설·이북 번호는 걸러진다), 확인을 눌러야 상태(기본 보는 중 · 봤음 · 보고 싶음)로 저장한다. 서재에 있는 건 대개 아직 보는 작품이고, 보는 중이어야 소식의 "이어 보기"에 잡히기 때문.
   이미 상태를 남긴 작품은 덮어쓰지 않는다. 수집 안 된 번호는 원하면 수집 대기열에 넣는다.

'내 서재' 페이지 마크업은 로그인해야 보여서 직접 확인하지 못했다. 그래서 특정 구조에 기대지 않고 페이지 전체에서
`productNo=` 만 찾는다.

## 큐 상태

```
pending ──fetch 성공──▶ done ──(7일 지나면 재수집)──▶ pending
   │
   ├──로그인 필요──▶ skipped
   └──오류──▶ failed (3번까지 재시도)
```

## 매너

- 요청 간격 1.5초 (`CRAWL_DELAY_SECONDS`) — 한 번 실행(400개)에 약 11분, 3시간마다
- 5xx/네트워크 오류는 지수 백오프로 최대 3번
- User-Agent 에 이 서비스 주소를 넣어 누가 요청하는지 알 수 있게

## 네이버가 마크업을 바꾸면

1. `uv run my-webtoon import <productNo>` 로 하나 가져와 보고 어떤 필드가 비는지 확인
2. 실제 페이지를 열어 바뀐 클래스명을 `parser.py` 에 반영
3. `tests/fixtures/detail_sample.html` 도 같은 구조로 고치고 `uv run pytest tests/test_parser.py`
