# 3. 추천 알고리즘

콘텐츠 기반 추천(content-based filtering). 4단계로 나뉘고 파일도 단계별로 하나씩이다.

## 1단계 — 작품 벡터 (`features.py`)

작품마다 두 벡터를 만들어 이어 붙인다.

**텍스트**: `제목 제목 줄거리` 를 글자 2~3-gram TF-IDF 로.

```
"회귀한 천마" → ["회귀", "귀한", "한 ", " 천", "천마", "회귀한", ...]
```

한국어는 조사·어미 때문에 "회귀한/회귀했다/회귀자" 가 단어 단위로는 전부 다른 단어지만, 글자 n-gram 이면
"회귀"를 공유한다. 형태소 분석기 없이도 꽤 잘 된다.

**메타**: 장르·해시태그·작가·출판사를 토큰 하나씩으로 본 TF-IDF.

```
["장르:무협", "#먼치킨", "#회귀", "작가:목하치수", "출판사:KOCM"]
```

TF-IDF 의 IDF 덕분에 흔한 토큰(예: "장르:소년")은 가볍고 드문 토큰(특정 작가)은 무겁다.

두 벡터는 각각 길이 1이므로 `[√0.5·텍스트, √0.5·메타]` 로 이어 붙이면

```
cos(A, B) = 0.5 · cos_텍스트(A, B) + 0.5 · cos_메타(A, B)
```

## 2단계 — 취향 벡터 (`profile.py`)

평가는 모든 칸이 선택 사항이다: 상태(봤음·보는 중·하차·보고 싶음·관심 없음 중 하나), 종합 점수 0~10,
세부 점수(스토리·작화·캐릭터·전개·몰입도, 각 0~10), 본 화수, 메모. 상태와 점수는 서로 독립이다.

```
취향 = Σ 가중치(평가) × 작품벡터       (Rocchio)

종합 점수가 있으면    (점수 - 4) × 0.4     → 10점 +2.4 | 8점 +1.6 | 6점 +0.8 | 4점 0 | 2점 -0.8 | 0점 -1.6
종합 점수가 없고 세부 점수만 있으면 → 세부 점수 평균을 종합 점수로
점수가 전혀 없으면 상태로            → 봤음 +0.5 | 보는 중 +0.5 | 보고 싶음 +0.8 | 하차 -0.8 | 관심 없음 -1.0
```

점수와 상태를 둘 다 남기면 점수가 이긴다 ("봤음"이어도 1점이면 싫어한 것). 평가를 남긴 작품은
상태와 상관없이 추천 후보에서 빠진다. 긍정 평가가 하나도 없으면 추천하지 않고
"많이 본 작품" 목록(콜드 스타트)에서 평가부터 하게 한다.

세부 점수는 지금은 "종합 점수가 없을 때의 대체값"으로만 쓴다. 평가가 쌓이면
"작화 점수를 높게 준 작품들의 공통점" 같은 항목별 취향을 따로 학습해 볼 수 있다(아래 실험 거리).

그 위에 `ProfileOptions` 세 가지: 긍정 가중치를 1.5제곱(10점이 7점보다 훨씬 세게), 부정 가중치는 절반(하차 하나가
장르 전체를 밀어내지 않게), 1년마다 반으로 줄되 절반 아래로는 안 가는 최신 평가 우선.

## 3단계 — 무료/회차 보정 (`scoring.py`)

질문: "3화만 무료인 건 제일 낮게, 회차가 많이 나온 건 위로" 를 어떻게 점수로?

```
최종 = 유사도 × (1 + a·무료점수 + b·회차점수 + c·평점점수)      기본 a=1.0, b=0.5, c=0.2

무료점수 = log(1+무료화수) / log(1+50)     → 3화 0.35, 10화 0.61, 50화+ 1.0, 전화 무료 1.0
회차점수 = log(1+총화수)   / log(1+300)    → 30화 0.60, 100화 0.81, 300화+ 1.0
평점점수 = (네이버 평점 - 8.5) / 1.5        → 대부분 9점대라 아래를 잘라 차이를 키운다
```

- **곱하기**를 쓰는 이유: 취향에 안 맞는(유사도≈0) 작품은 무료가 아무리 많아도 올라오면 안 된다.
- **로그**를 쓰는 이유: 3→30화 무료는 큰 차이지만 300→330화는 거의 같다(수확 체감).
- **맨 아래로(sink)**: 무료가 3화 이하면(전화 무료 제외) 점수와 상관없이 목록 뒤로 보낸다.
  곱셈 보정만으로는 아주 비슷한 유료작이 덜 비슷한 무료작을 이길 수 있어서, "제일 낮게"를 확실히 하려고
  정렬 키를 `(유료위주 여부, -점수)` 로 둔다. 화면에서 끌 수도 있다.
- **단행본**은 1권 ≈ 8화로 환산한다 (`VOLUME_TO_EPISODES`). "1권 무료"는 유료 위주로 보지 않는다.

모든 값은 메인 화면의 "점수 공식 조정하기"에서 바꿔 볼 수 있고, 카드마다
`유사도 0.134 × 보정 2.58 = 0.346` 처럼 계산이 그대로 찍힌다.

## 4단계 — 엮기와 설명 (`engine.py`)

- 작품 벡터는 메모리에 캐시하고 `(작품 수, 마지막 수집 시각)` 이 바뀔 때만 다시 만든다.
- 이미 평가한 작품(봤음·관심없음 포함)은 후보에서 뺀다. 성인 작품은 기본 제외.
- "닮은 작품": 내가 좋아한 작품 중 이 후보와 코사인이 가장 큰 것.
- 태그 칩: 후보의 메타 토큰 중 내가 좋아한 작품들에도 있는 것, 가중치 큰 순 4개.

## 평가한 작품의 유사도 — 자기 몫 빼기

'본 것 포함'·'본 것만' 추천(`?reviewed=include|only`)과 작품 상세의 **추천도**에서는 이미 평가한 작품도 점수를 매긴다.
그냥 계산하면 10점 준 작품은 취향 벡터에 자기 자신이 들어 있어서 당연히 1등이 된다. 그래서 그 작품의 평가를 뺀 취향과
비교한다(`profile.taste_similarities`). 다시 계산하지 않고 식으로 뺀다 — 취향 P = Σ w·x, 작품 i 를 빼면
x_i·(P - w_i·x_i) = x_i·P - w_i, |P - w_i·x_i|² = |P|² - 2·w_i·(x_i·P) + w_i² (x 는 길이 1).

**추천도** (`engine.match_score`, 0~100) = 이 작품보다 최종 점수가 낮은 작품의 비율(내림). 100 은 1등뿐이다.
유사도 값(0.1~0.5)은 크기가 직관적이지 않아서 백분위로 바꿨다. 옆에 '취향 일치'(보정 없이 유사도만의 백분위)도 보여 준다.

## 다양화 (MMR)

점수순 그대로면 좋아한 작품 하나와 닮은 작품(같은 작가·같은 시리즈)이 위를 다 채운다. 그래서 앞쪽 150개를
한 장씩 다시 고르면서 "이미 고른 것과 겹치는 정도"를 벌점으로 뺀다 (`engine._diversify`):

    다음 = argmax  (1-d) × 점수/최고점수  -  d × max(이미 고른 작품과의 유사도)

`d = ScoringOptions.diversity` (기본 0.3, 화면의 '점수 공식 조정'에서 바꿀 수 있다). '유료 위주' 묶음은 섞지 않고 맨 뒤에 둔다.

## 판본 묶기와 순위 스냅숏

- **판본 묶기** (`works.py`): '나루토'(화)와 '나루토 [단행본]'(권)처럼 한 작품이 여러 상품으로 올라온 경우(수집분 기준 145쌍),
  대괄호 꼬리표·공백·문장부호를 뗀 제목이 같고 **작가가 하나라도 겹치면** 한 작품으로 본다. 작가 이름은 대소문자·성이름 순서를
  무시한다('Ukyo kodachi' = 'KODACHI Ukyo'). 제목만 같은 다른 작가의 작품은 나눈다. 추천에는 점수 높은 판본 하나만 나오고
  ("다른 판본 1개"), 어느 판본이든 평가했으면 나머지도 빠진다.
- **순위 스냅숏**: 무한 스크롤에서 다음 페이지를 매번 새로 계산하면, 스크롤 중에 평가를 남겨 취향이 바뀌는 순간
  순위가 밀려 같은 작품이 두 번 나오거나 건너뛴다. 그래서 첫 페이지에서 전체 순위를 한 번 계산해 `rec_snapshots` 테이블에
  두고(30분), 다음 페이지는 거기서 자른다(`?snap=`). 메모리가 아니라 DB 에 두는 건 무중단 배포 중 옛 파드·새 파드가
  번갈아 요청을 받아도 같은 순위를 이어 가게 하려고. 새로고침하면 새 평가가 반영된 순위를 다시 만든다.

## 품질 측정 (`evaluate.py`, `my-webtoon eval <아이디>`)

가중치는 감이 아니라 이걸로 고른다. **leave-one-out**: 좋게 평가한 작품을 하나씩 숨기고(같은 작품의 다른 판본 평가도 같이),
나머지 평가로 순위를 만든 뒤 숨긴 작품이 몇 위에 나오는지 본다. HR@10·HR@30(10위/30위 안에 든 비율), MRR(1/순위 평균),
중앙 순위, 그리고 실제 추천 상위 30개의 작가 수·평균 쌍 유사도(다양성).

2026-10-25, singun11 의 좋게 본 평가 29개 기준:

| 설정 | HR@10 | HR@30 | MRR | 중앙 순위 |
|---|---|---|---|---|
| 예전 (텍스트 .5 : 메타 .5, 평탄 프로필, 다양화 없음) | 24.1% | 44.8% | 0.166 | 36 |
| **지금** (텍스트 .7 : 메타 .3, 고득점 강조·부정 절반, 다양화 .3) | **31.0%** | **62.1%** | **0.178** | **26** |
| 지금에서 다양화만 끔 | 31.0% | 51.7% | 0.176 | 27 |
| 텍스트 .3 : 메타 .7 | 24.1% | 48.3% | 0.159 | 32 |
| 유사도만 (무료·회차 보정 끔) | 24.1% | 31.0% | 0.157 | 56 |

읽는 법: 29개뿐이라 한 칸(1개) 차이가 3.4%p 다. 큰 차이만 믿는다. 무료·회차 보정을 끄면 오히려 나빠지는 건
"사람들이 실제로 본 작품 = 무료 많고 긴 인기작"이라서다.

**문장 임베딩은 해 봤지만 넣지 않았다.** 다국어 문장 임베딩(paraphrase-multilingual MiniLM-L12 / mpnet-base, ONNX)을
줄거리에 씌워 TF-IDF 와 섞어 봤다. 그대로 쓰면 모든 작품끼리 유사도가 0.6 근처로 비슷해져서(평균 쌍 유사도 0.6) 크게 나빠졌고
(HR@30 62% → 28~48%), 평균 벡터를 빼(centering) 보정해도 가장 나은 조합이 HR@30 65.5%(+1개), MRR 은 0.178 → 0.125 로
오히려 떨어졌다. 이미지가 300MB 넘게 커지는 것에 비해 이득이 없다. 평가가 수백 개로 늘면 다시 재 볼 만하다.
