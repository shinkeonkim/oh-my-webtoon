# 1. 아키텍처와 설계 결정

## 구성 요소

```
my_webtoon/
├── config.py          환경변수 → Settings
├── schema.sql / db.py SQLite. ORM 없이 SQL 을 그대로 둔다
├── crawler/
│   ├── client.py      정중한 HTTP 클라이언트 (간격, robots.txt, 재시도)
│   ├── parser.py      HTML → dict (순수 함수)
│   ├── seeds.py       BFS 출발 페이지
│   └── runner.py      run_once() + BackgroundCrawler 스레드
├── recommender/
│   ├── features.py    작품 → 벡터
│   ├── profile.py     평가 → 취향 벡터
│   ├── scoring.py     무료/회차/평점 보정
│   └── engine.py      추천 목록 + 설명, 벡터 캐시
├── web/
│   ├── app.py         FastAPI 라우트
│   ├── auth.py        비밀번호 (PBKDF2 해시, 세션 epoch)
│   ├── templates/     Jinja2 (_card.html, _review.html, _review_form.html 이 재사용 조각)
│   └── static/        style.css, htmx.min.js (CDN 없이 동봉)
├── backup.py          하루 한 번 DB 사본 + 평가 JSON (BACKUP_DIR), 내보내기/가져오기
└── cli.py             serve / crawl / import
```

## 왜 이렇게 골랐나

| 결정 | 이유 | 대안과 바꿀 시점 |
|---|---|---|
| **Python 하나로** | 크롤링(httpx+BeautifulSoup), 추천(scikit-learn), 웹(FastAPI)이 모두 가장 짧은 코드로 된다. 공부할 때 언어를 오가지 않아도 된다 | — |
| **SQLite, ORM 없음** | 쓰는 주체가 하나. 쿼리가 코드에 그대로 보인다 | 여러 파드가 동시에 쓰게 되면 Postgres(CNPG) |
| **서버 렌더링 + HTMX** | 프론트엔드 빌드 없이 HTML 템플릿만 읽으면 된다. 별점 클릭은 `_rate.html` 조각만 서버에서 다시 받아 교체 | 화면이 복잡해지면 React 등 |
| **크롤러를 웹 프로세스 안 스레드로** | SQLite 파일(PVC, ReadWriteOnce)을 쓰는 파드를 하나로 유지. CronJob 을 따로 두면 같은 노드에 붙어야 하는 제약이 생긴다 | Postgres 로 옮기면 CronJob 분리 |
| **콘텐츠 기반 추천** | 사용자가 나 하나라 협업 필터링(다른 사람 평가) 데이터가 없다 | 아래 "다음 단계" |
| **추천 이유를 화면에 노출** | "유사도 × 보정 = 점수", 닮은 작품, 겹치는 태그를 보여 줘서 공식을 바꿨을 때 결과가 어떻게 달라지는지 바로 보인다 | — |

## 요청 하나의 흐름 (예: 추천 카드에서 8점 클릭)

1. `_review.html` 의 버튼: `hx-post="/reviews/123" hx-vals='{"score": "8", "toggle": "score"}'`
2. `app.py: save_review()` → `parse_review_form()` 이 "score 칸만 8로" 라는 변경분을 만든다
   (이미 8점이었으면 toggle 이라 "score 칸 비우기")
3. `db.update_review()` 가 그 칸만 바꿔 `reviews` 에 upsert — 상태·메모·세부 점수는 그대로
4. HX-Request 헤더가 있으니 `_review.html` 조각만 렌더링해서 응답 → HTMX 가 위젯을 교체
5. 다음에 `/` 를 열면 `engine.recommend()` 가 새 평가로 취향 벡터를 다시 계산
   (작품 벡터는 캐시, 취향 벡터는 매번 계산 — 평가 수십 개 정도는 밀리초 단위)

"자세히"를 누르면 `GET /reviews/123/edit` 가 `_review_form.html` 로 위젯을 바꾸고, 그 폼은 `full=1` 로
모든 칸을 한 번에 보낸다 (빈 칸 = 비우기).

## 다음 단계 아이디어 (공부 거리)

- **임베딩**: TF-IDF 대신 문장 임베딩(홈랩 LiteLLM 게이트웨이의 임베딩 모델)으로 줄거리 의미 유사도
- **학습형 랭킹**: 평가가 쌓이면 (유사도, 무료점수, 회차점수, 평점, 장르…) → 내 별점 을 로지스틱 회귀로 학습해
  `scoring.py` 의 손으로 정한 가중치를 데이터로 대체
- **다양성**: MMR(Maximal Marginal Relevance)로 비슷한 작품만 몰리지 않게
- **같은 작품 변형 묶기**: "[단행본]", "[개정판]" 같은 판본을 하나로 묶기
